# Проверки публичного ядра

## Воспроизведение

Из корня репозитория:

```sh
python3.13 -m venv .venv
.venv/bin/python -m pip install -r server/requirements.txt
.venv/bin/python -m pip check
(cd server; ../.venv/bin/python -B -W error::ResourceWarning -m unittest discover -s tests -v)

(cd device; GOWORK=off GOTOOLCHAIN=go1.27.3 GOFLAGS=-mod=readonly go test -count=1 ./...)
(cd device; GOWORK=off GOTOOLCHAIN=go1.27.3 GOFLAGS=-mod=readonly go test -race -count=1 ./...)
(cd device; GOWORK=off GOTOOLCHAIN=go1.27.3 GOFLAGS=-mod=readonly go vet ./...)
(cd device; GOWORK=off GOTOOLCHAIN=go1.27.3 GOFLAGS=-mod=readonly go mod verify)
```

Тесты Unix sockets создают временный socket под каталогом модуля; путь checkout должен быть достаточно коротким, чтобы полный путь сокета укладывался в Linux `sun_path` (107 байт). Для длинного дерева сначала сделай чистую копию в коротком временном каталоге. Это ограничение тестового стенда, не повод отключать проверку длины пути в приложении.

## Фактически исполнено перед публикацией

- **Python 3.13:** 44 unittest; настоящий движок, локальные aiohttp HTTP/WS и контролируемые границы ASR/VAD/LLM/времени. Проверены запрет аудио до состояния, mute/off-подобная блокировка, heartbeat, очередь 2 с, пауза, 15-секундный cooldown, новый голос, запоздавший ответ, reset/cancel, ошибки JSON/секрет-файлов, busy до окончания реального обработчика и отсутствие текста/секретов в health.
- **Go 1.27.3:** 33 верхнеуровневых теста и 17 подтестов, обычный и race-запуск, `go vet`, `go mod verify`, статическая Linux/ARM64-сборка. Тесты используют синтетический PCM и локальные TLS/WebSocket/Glagol-стенды. Клиентская команда собирается, но не запускается на реальном ARM64-устройстве в рамках этой публикации.
- **Отдельная локальная ASR-проба:** настоящий Vosk и WebRTC VAD распознали заранее созданную синтетическую русскую фразу; реальный авторизованный WS передал PCM с обычным темпом, локальный HTTP-стенд получил распознанный текст и вернул явно заданную тестовую реплику. Проверены пауза, ограничение очереди, очистка контекста после off и отсутствие стенограммы в health. Проба не обращалась к внешней LLM. Аудио и модель не входят в репозиторий.

Замена приватного alias на `conversation-model` проверена RED→GREEN: сначала тест ожидал новое имя и падал на прежнем, после изменения двух значений по умолчанию полный набор прошёл. Других изменений рабочего Python-движка и Go-клиента нет.

В первом GitHub-прогоне Go-тесты выявили зависимость фикстур от umask: `t.TempDir()` создавал `0755`, а клиент требует приватный каталог `0700`. Отказ воспроизведён локально при `0022`; затем только тестовые каталоги состояния получили явный `chmod 0700`. Полные normal/race-наборы повторены при `0022` и `0077`: по 33 теста и 17 подтестов, PASS. Рабочие `.go`-файлы и проверка приватности не менялись.

CI повторяет Python-тесты и Go/race/vet/checksum/ARM64. Исходники проверяются отдельно от готовности hardware.

## Что не проверено этой публикацией

- Свежая установка на колонку, реальный микрофон, слышимая речь и поведение аппаратного mute.
- Работа в другой сети, VPN, автозапуск и восстановление конкретного устройства.
- Надёжность отделения телевизора/музыки, распознавание множества голосов, качество и уместность реальных ответов модели.
- Универсальная совместимость прошивок, полный аудит CVE или прав на сторонние бинарники.

Одна чистая синтетическая фраза не является ASR-бенчмарком на реальной комнате. Успешные loopback-тесты не подтверждают домашнюю/офисную сеть, а статическая ARM64-сборка не доказывает работу колонки.
